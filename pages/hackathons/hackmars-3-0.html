About the Project


Inspiration: Mackenzie suggested the idea — and once we started we both got completely swept up in it. We wanted to build something that actually integrates with the tools people use every day, not just a toy demo. Google Calendar and Gmail are where real scheduling lives, so that became the target.

What it does: Calendar AI Assistant connects to your Google Calendar and Gmail through OAuth, then lets you talk to your schedule in plain English. Ask it to add an event, summarise your week, create a todo from an email, or build an optimized daily plan from a list of tasks. A 4-agent CrewAI pipeline handles the request end-to-end: one agent analyses your intent, one retrieves the relevant schedule data, one processes and acts on it, and one verifies the result before it comes back to you. Available as both a Streamlit Web UI and a CLI.

How it was built: Python core with CrewAI managing the agent pipeline. Google Calendar API and Gmail API for data access, authenticated via OAuth. Streamlit for the Web UI. A separate planner agent that can take a list of tasks and output an optimized time-blocked schedule. Config and secrets stored in TOML files; calendar events and todos persisted as JSON.

Challenges: OAuth credential handling across environments was the biggest friction point — getting the token flow to work consistently for both teammates and in different runtime contexts required multiple iterations. Keeping the CLI and Web UI in sync as features were added was also non-trivial.

What we learned: Building with the Google API ecosystem end-to-end, including the OAuth consent flow, scopes, and credential caching. Also learned how to structure a CrewAI project so agents stay focused — overly broad agent goals produce unpredictable results.

What's next: Recurring event support, smarter conflict detection, and potentially a reminder push notification layer.

Dev Notes

Tech Stack

Python + CrewAI (agent pipeline), Google Calendar API + Gmail API (data), Streamlit (Web UI), CLI (rich terminal). Config/secrets in TOML; event/todo state in JSON.

Hardest Part

Google OAuth across two developers and two runtime modes (CLI vs. Web UI). The token refresh logic had to be airtight — a stale token mid-pipeline breaks the whole crew. Also keeping CLI and Streamlit page feature parity as things changed.

What I'd Do Differently

Abstract the Google API calls into a single data layer early on instead of letting both the CLI and Web UI talk to the API directly. Would have made adding features much cleaner and avoided several sync bugs.
