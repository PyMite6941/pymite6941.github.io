Description


Context: Days 27–29 of the 30 Days challenge built the Forge language — from a four-command interpreter to a full Forge-to-Python compiler. For the final day I wanted to wrap the whole thing in something that felt like a product — not just a terminal, but an operating system.

Challenges: Re-implementing the Forge interpreter in JavaScript required handling the ask command as stateful async flow rather than a blocking call. Draggable windows required tracking mouse offsets and cleaning up event listeners to avoid accumulating handlers. The matrix easter egg needed careful canvas timing to layer over the OS without disrupting window state.

Result: A full simulated OS with three core apps (Terminal, My Sites, About), a live taskbar clock, multiple hidden commands (matrix, hack nasa, sudo rm -rf /, whoami), a clock easter egg that unlocks a Vault window, and a Konami code trigger. All windows are draggable, minimizable, and maximizable. Built in JavaScript/HTML/CSS as the Day 30 capstone of the 30 Days of AI Prompts challenge.

How It Works


Forge Language — Interpreter Pipeline ════════════════════════════════════════ user types: "let x = 10 + 5" │ ▼ ┌───────────────────────────────┐ │ Lexer │ │ tokenise input string │ │ "let" "x" "=" "10" "+" "5" │ └───────────────┬───────────────┘ │ token list ▼ ┌───────────────────────────────┐ │ Parser │ │ Assign( │ │ id = "x", │ │ expr = BinOp(Num(10), │ │ +, │ │ Num(5)) │ │ ) │ └───────────────┬───────────────┘ │ AST ▼ ┌───────────────────────────────┐ │ Interpreter │ │ walk AST, evaluate nodes │ │ BinOp → 10 + 5 = 15 │ │ Assign → env["x"] = 15 │ └───────────────┬───────────────┘ ▼ output to terminal widget Supported constructs: ────────────────────── let x = expr variable assignment print expr output ask "prompt" → var async input (stateful flag) if / else conditionals loop N times counted iteration Interpreter written in Python originally, then ported to JavaScript for the browser — same grammar, different host language.

Window Manager — Drag Event Flow ═══════════════════════════════════ mousedown on title bar │ ▼ record offset: offsetX = event.clientX - window.offsetLeft offsetY = event.clientY - window.offsetTop attach mousemove + mouseup to document │ ▼ on every mousemove window.style.left = event.clientX - offsetX + "px" window.style.top = event.clientY - offsetY + "px" │ ▼ on mouseup removeEventListener("mousemove", onDrag) ◄── CRITICAL removeEventListener("mouseup", onRelease) ◄── skip this and handlers stack on every re-open → leak ask command — async input workaround: ────────────────────────────────────── Python input() blocks the thread. Browser JS is single-threaded — no blocking. Fix: global askingFor flag interpreter hits "ask" node → set askingFor = "varName", return early user presses Enter in terminal → if askingFor: env[askingFor] = value askingFor = null, resume interpreter The async ask workaround was the hardest part of porting Forge from Python to JavaScript.

Dev Notes

Problems Solved

Days 27–29 built the Forge language but it lived as a plain terminal script. For the capstone I wanted to ship it as something that felt like a real product — a simulated OS that showcased the language inside a full desktop environment.

Errors & Fixes

The ask command in Python blocks on input(), but in a browser there's no blocking — solved with a global askingFor flag that routes the next input line to the waiting variable instead of the interpreter. Drag event listeners accumulated on re-opened windows causing a memory leak; fixed by calling removeEventListener in the mouseup handler.

What I Learned

Browser event model — the mousedown/mousemove/mouseup drag pattern and why cleanup matters. Async state machines in JavaScript, canvas layering for the matrix easter egg, and what it takes to reimplement a language interpreter in a different language (Python → JS).
