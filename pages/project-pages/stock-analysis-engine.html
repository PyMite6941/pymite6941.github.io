Description


Why I built it: My grandfather got me interested in stocks and investing from a young age. He was the one who first sat me down and explained what it actually means to own a piece of a company — how a share price moves, why patience beats panic, and how to read a market without letting it read you. That early influence stuck with me, and this project is the engineering version of those lessons: a tool that turns raw market data into the kind of clear, honest picture he always pushed me to look for before making a decision.

Context: Most retail stock tools either bury you in noise or hide the math behind a paywall and a black-box "AI signal." I wanted the opposite — a tool where the numbers are computed transparently from real data, the AI explains tradeoffs instead of barking buy/sell calls, and the whole analysis still works offline with no keys at all.

Challenges: The hardest design goal was guaranteeing that the offline Streamlit math is identical to the online API math. I solved it by putting every calculation in a shared core/ package that both paths import — the AI lives only in the backend and never touches the numbers. Deploying a React frontend and a FastAPI backend as a single same-origin Vercel project (to avoid CORS) and making stock data reliable from cloud IPs were the other two real hurdles.

Result: A deployed full-stack analysis engine: live quotes and price history, computed risk metrics, candlestick charts with technical indicators, CSV export, and a data-grounded AI analyst — backed by a Groq → OpenRouter fallback chain so a dead key never takes the app down. The same core math also powers a local Streamlit app that needs no API keys.

Dev Notes

Problems Solved

Retail stock tools tend to either drown you in noise or hide the math behind a black-box "AI signal." I wanted transparent, deterministic numbers, an AI that explains tradeoffs instead of giving directives, and an analysis path that still runs offline with no keys — the disciplined, evidence-first approach to investing my grandfather taught me.

Errors & Fixes

yfinance is unreliable from cloud IPs, so production silently returned empty quotes — fixed by making the data layer pluggable and switching the deployed app to a Finnhub REST provider. CORS errors between the React frontend and FastAPI backend disappeared once I deployed both as one same-origin Vercel project (static frontend + a @vercel/python function), with the frontend calling relative /api/....

What I Learned

How to architect shared business logic so two completely different frontends (a React SPA and a Streamlit app) compute identical results from one core/ package. Plus implementing technical indicators from scratch with proper warm-up handling, building a multi-provider AI fallback chain over the OpenAI-compatible wire format, and shipping a hybrid Python + React app on a single Vercel deployment.


Not financial advice — the AI explains tradeoffs, it doesn't give buy/sell calls.
