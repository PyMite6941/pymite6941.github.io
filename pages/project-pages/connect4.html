Description


Context: The NOAI competition requires implementing game-playing AI from scratch — no ML libraries, pure algorithm design. I needed a practice project that forced me to implement real search and evaluation logic.

Challenges: Writing a DFS-based minimax evaluator that's fast enough to be playable in real time. A transposition table and symmetry caching were added to avoid re-evaluating equivalent board states. I also had to build a pixel-based board reader to interface with the game running on screen, without any game API.

Result: A fully functioning Connect 4 AI that plays strong moves in real time, reading live game state from the screen via pixel detection. The minimax + transposition table combination keeps decision time under a second per move.

In Action


Dev Notes

Problems Solved

The NOAI competition requires game-playing AI built from scratch — no ML libraries. I needed a practice project that forced a real implementation of search and board evaluation, plus a way to interface with the game running on screen without any game API.

Errors & Fixes

The initial DFS was too slow for real-time play at competitive depth — adding a transposition table and symmetry caching cut per-move decision time to under a second. Pixel detection coordinates were hardcoded and broke at different screen resolutions; fixed by adding a calibration step on startup.

What I Learned

Minimax with transposition tables, board symmetry pruning, and how to profile and speed up Python search code. Also learned pixel-based game state reading — capturing screen regions, converting to a grid, and mapping colors to board positions.
